Joins are the quiet connective tissue of relational work. They let you answer questions that span more than one table without flattening your data model.

INNER JOIN

An inner join returns rows where the join condition matches on both sides.

SELECT o.order_id, c.name
FROM orders AS o
INNER JOIN customers AS c ON c.id = o.customer_id;

LEFT JOIN

A left join keeps every row from the left table. When there is no matching right-side row, the right-side columns are NULL.

SELECT c.name, o.order_id
FROM customers AS c
LEFT JOIN orders AS o ON o.customer_id = c.id;

This is one of the most common joins in analytics and data pipelines. It helps answer questions like "show every customer, along with any orders they have placed." If a customer has never placed an order, the query still returns that customer with a NULL order value instead of dropping them from the result set.

RIGHT JOIN

A right join preserves every row from the right table. It is less common than a left join, but it is useful when the right table is the one that should remain complete in the result.

SELECT c.name, o.order_id
FROM customers AS c
RIGHT JOIN orders AS o ON o.customer_id = c.id;

In practice, many teams rewrite right joins as left joins by swapping table order, because left joins are easier to read and reason about.

FULL OUTER JOIN

A full outer join returns all rows from both tables. Rows with matches appear together, while unmatched rows from either side remain with NULL values in the columns from the other side.

SELECT c.name, o.order_id
FROM customers AS c
FULL OUTER JOIN orders AS o ON o.customer_id = c.id;

This is useful when you want a complete picture of both datasets, such as comparing customers with orders or identifying missing records on either side. It is especially helpful in data quality checks and reconciliation tasks.

When to use which join

  • INNER JOIN: Use when you want only matching rows.
  • LEFT JOIN: Use when the left table is the source of truth and you want to keep every row from it.
  • RIGHT JOIN: Use when the right table is the one you need to preserve.
  • FULL OUTER JOIN: Use when you need to see both matching and non-matching records from both tables.

One subtle but important point: the join condition determines which rows match. If your keys are duplicated in one or both tables, the result can multiply rows, which may be correct or may reveal a data problem. Always validate row counts and key uniqueness before drawing conclusions from a join.

Key takeaways

  • Choose the preserved side deliberately.
  • Check key uniqueness before joining.
  • Filter joined data with care: a WHERE condition can remove the NULL rows you intended to preserve.
  • Match the join type to the business question. Different joins answer different data questions even when the tables are the same.
Interview tip: Explain both the result shape and the business meaning of the join. That is usually more valuable than reciting syntax.
